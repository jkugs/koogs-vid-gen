# 003 - Iteration 2: Identity-Preserving Starting Frame Generation

## Where We Are

Iteration 1 proved the basic image-to-video workflow works.

We successfully ran:

```text
real photo -> Wan 2.2 -> MP4
```

on a RunPod L40S.

Two real generations were tested using `inputs/me.jpg`:

1. A basic smiling/motion clip.
2. A clip where the subject closes their eyes and turns their head to the right.

The results were recognizably the same person and generally temporally coherent. The second test showed some visible generative artifacts around the eye-closing motion, but overall the result was good enough to validate the basic workflow.

At this point, further testing of small Wan motions is not the highest-priority problem.

Iteration 1 should be considered a successful proof of concept.

---

## The Next Problem

The current pipeline is constrained by the composition of the source photograph.

For example:

```text
photo of person leaning toward camera
        |
        v
       Wan
        |
        v
video beginning from approximately that composition
```

Wan can animate the image, but it does not solve the larger filmmaking problem:

> How do we put a specific person into an arbitrary new shot while preserving their identity?

For filmmaking, we eventually want to be able to produce shots such as:

- the person standing in a hallway
- a side profile
- a medium shot in another location
- the person wearing different clothing
- different camera framing
- different lighting
- different poses

while still clearly depicting the same person.

---

## Iteration 2 Goal

Introduce a starting-frame generation stage before Wan.

The target pipeline becomes:

```text
Reference image(s)
        +
Shot description
        |
        v
Starting-frame generator
        |
        v
Generated still image
        |
        v
Wan 2.2
        |
        v
Video
```

The starting-frame generator is responsible for things such as:

- identity
- pose
- composition
- environment
- clothing
- lighting
- initial camera framing

Wan remains responsible primarily for motion over time.

The immediate proof we want is:

> Can we take the existing reference photo, generate a substantially different starting image that still resembles the same person, and then successfully animate that generated frame with the existing Wan pipeline?

Image quality does not need to be perfect yet.

---

## Architecture Principle

Do not tightly couple the project to the image model selected for this experiment.

The eventual conceptual interface should be approximately:

```python
generate_start_frame(
    reference_images=[...],
    prompt="...",
    output_path="..."
)
```

The implementation underneath that operation should be replaceable.

Iteration 2 may use a relatively small quantized model. Future versions may use:

- larger image-editing models
- better reference-image conditioning
- identity adapters
- LoRAs
- fine-tuned character models
- face refinement
- other techniques that do not yet exist

The rest of the video pipeline should not care which implementation produced the starting frame.

Keep this iteration small and explicit. Do not build a general plugin/model framework yet.

## Exact Current Stopping Point

Do not immediately build a large image-generation abstraction.

The next technical task is:

> Verify that Diffusers can load the local Q4 GGUF Qwen transformer together with the locally downloaded Qwen supporting components.

The first test should ONLY instantiate the transformer and pipeline. It should
not move the entire pipeline to CUDA or perform inference.

Do not perform image inference until model loading succeeds.

GGUF loading is supported at the individual Diffusers model-component level,
not directly at the pipeline level. Load the quantized transformer first and
then inject it into the pipeline.

The intended local-only loading pattern is approximately:

```python
from pathlib import Path

import torch
from diffusers import (
    GGUFQuantizationConfig,
    QwenImageEditPlusPipeline,
    QwenImageTransformer2DModel,
)

model_dir = Path("/workspace/models/qwen-image-edit-2511")
base_dir = model_dir / "base"
gguf_path = model_dir / "qwen-image-edit-2511-Q4_0.gguf"

transformer = QwenImageTransformer2DModel.from_single_file(
    gguf_path,
    config=base_dir,
    subfolder="transformer",
    quantization_config=GGUFQuantizationConfig(
        compute_dtype=torch.bfloat16,
    ),
    dtype=torch.bfloat16,
)

pipeline = QwenImageEditPlusPipeline.from_pretrained(
    base_dir,
    transformer=transformer,
    dtype=torch.bfloat16,
    local_files_only=True,
)
```

Passing the local transformer configuration explicitly is important for a
Diffusers-format GGUF checkpoint. `local_files_only=True` ensures this test
fails clearly if any supporting component is missing instead of silently
downloading additional files.

For the later inference test, prefer
`pipeline.enable_model_cpu_offload(device="cuda")` over moving the entire
pipeline to CUDA. The quantized transformer is smaller, but the BF16 text
encoder, VAE, activations, and other components still require significant
memory.

Once the pipeline loads successfully, the next step will be a minimal `generate_image.py`.

## First Planned Image Experiment

Use the same reference photograph from Iteration 1.

The first test should make a substantial scene/composition change while explicitly asking the model to preserve the person's identity.

Example concept:

```text
Place the person in a dimly lit hotel hallway at night.
Medium shot, cinematic realistic lighting.
Preserve the person's facial identity and appearance.
```

The purpose is NOT merely to make an attractive image.

We specifically want to evaluate:

1. Does the result still look like the reference person?
2. Can the model substantially change the scene/composition?
3. Does the resulting frame look suitable as input to Wan?
4. Can Wan subsequently animate it successfully?

If those work, we will have demonstrated the first primitive two-stage filmmaking pipeline:

```text
reference person
      |
      v
Qwen Image Edit
      |
      v
new shot / starting frame
      |
      v
Wan 2.2
      |
      v
video shot
```

That is the main objective of Iteration 2.
