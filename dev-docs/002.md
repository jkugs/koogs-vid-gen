## Where We Left Off

## Decisions

- Use `Wan-AI/Wan2.2-TI2V-5B-Diffusers` for the first experiment.
- Use the Diffusers `WanImageToVideoPipeline`, not ComfyUI or a cloned Wan
  repository.
- Use Python 3.11 with `uv`.
- Pin PyTorch 2.8.0 and Torchvision 0.23.0 to the CUDA 12.8 wheel index so they
  match the selected RunPod template.
- Generate approximately five seconds at 24 FPS using 121 frames and 50
  inference steps.
- Keep the implementation explicit and single-model. Do not build application
  infrastructure or generalized abstractions during Iteration 1.

## Current Script

`generate_video.py` currently:

- accepts `--image`, `--prompt`, `--output`, and `--seed`;
- defaults to `inputs/input.jpg` and `outputs/output.mp4`;
- validates the image and prompt before importing heavy libraries;
- requires CUDA;
- loads the Wan VAE in float32 and the pipeline in bfloat16;
- uses Diffusers model CPU offloading to keep peak GPU memory within the L40S's
  available VRAM;
- preserves the input aspect ratio within a `1280 * 704` target area;
- generates 121 frames at 24 FPS with 50 steps and guidance scale 5.0;
- exports a standard MP4;
- reports the GPU, parameters, resolution, loading time, inference time, export
  time, total time, and VRAM use;
- prints stage markers so long operations do not appear frozen.

Local checks passed for syntax, CLI defaults, missing/invalid inputs, dimension
calculation, lockfile integrity, and a mocked end-to-end workflow. A full local
Diffusers import was blocked because the workstation's asdf Python 3.11 build
lacks the standard `_bz2` extension. This is a workstation Python issue, not a
project dependency issue.

## First Generation

A private photograph named `me.jpg` was placed in the ignored `inputs/`
directory on the pod. The intended first run was:

```bash
cd /workspace/koogs-vid-gen
source /workspace/pod-env.sh
uv run --no-sync python generate_video.py \
  --image inputs/me.jpg \
  --output outputs/me-smile.mp4
```

The default prompt asks the person to slowly turn toward the camera and smile
while the camera remains stationary.

The first attempt completed denoising but failed during VAE decoding before MP4
export. PyTorch reported a CUDA out-of-memory error while trying to allocate
another 1.64 GiB: 43.83 GiB of the L40S's 44.39 GiB usable VRAM was already in
use. Consequently, no output file was created by that attempt.

The script was changed from moving the entire pipeline to CUDA with
`pipeline.to(device)` to using:

```python
pipeline.enable_model_cpu_offload(device="cuda")
```

The same generation was then rerun successfully. It created
`outputs/me-smile.mp4`, which was copied back to the local project. Visual
inspection confirmed that the source image was animated: the subject, who was
already facing the camera, smiled slightly more. This was a successful
Iteration 1 proof of concept.
